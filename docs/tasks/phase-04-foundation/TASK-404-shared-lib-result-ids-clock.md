## 1. Objective

Create the three cross-cutting primitives every other layer uses: a `Result<T, E>` type, a client-side ID generator that doubles as an idempotency key, and the injectable `Clock` that is the only place the device time is read.

## 2. Background and Context

- SA §E.2 requires services to return `Result` and never throw to the UI.
- DB §B.0: IDs are `<prefix>_<time36>_<rand>` generated by `shared/lib/ids.ts`; client IDs are the idempotency key for FR-026.4.
- BL §C.2: `Clock.today()` is the only source of "today", built from **local** date components (never `new Date('YYYY-MM-DD')`).
- TS §0: Clock and ID generator must be injectable with deterministic test doubles.

## 3. Requirements

1. `result.ts`: `type Result<T, E> = { ok: true; value: T } | { ok: false; error: E }`, plus `ok()`, `err()`, `isOk()`, `isErr()`. No exceptions, no classes.
2. `ids.ts`: `newId(prefix: IdPrefix): string` → `${prefix}_${Date.now().toString(36)}_${16 hex chars from 64 random bits}`. `IdPrefix` is a union: `'tx' | 'bv' | 'goal' | 'gbe'`. Randomness from `crypto.getRandomValues` (available in Hermes/RN 0.86; verify) with no new dependency (DEP §4 rejects `uuid`/`expo-crypto`). Provide `createIdGenerator(seed?)` for deterministic tests.
3. `clock.ts`: `interface Clock { today(): LocalDateString; nowIso(): string }`; `systemClock` builds `today` from `getFullYear()/getMonth()+1/getDate()`, zero-padded; `nowIso()` returns UTC `toISOString()` (milliseconds, `Z`). `createFixedClock(today, nowIso)` for tests. Return the date as a plain `string` here; TASK-408 introduces the branded `LocalDate` and its constructor, and this file must then use it (TASK-408 owns that edit).
4. No module in this task imports React or Expo.
